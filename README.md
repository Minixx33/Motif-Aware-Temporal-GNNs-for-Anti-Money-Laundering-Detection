# Motif-Aware Temporal GNNs for Anti-Money Laundering Detection

**MLR 570 Course Project**

This project trains Graph Neural Network (GNN) models on the IBM AML transaction dataset to detect laundering edges (transactions). On top of the raw transaction graph we inject **criminology-theory features** (Routine Activity Theory — RAT) and **graph motif features** (fan-in, fan-out, chain, cycle), and study how these features improve detection on imbalanced AML data.

Models supported:

- **GraphSAGE** — static graph baseline (edge classifier).
- **GraphSAGE-T** — GraphSAGE with sinusoidal time encoding on edges (Temporal GraphSAGE).
- **DyRep** — simplified DyRep-style temporal event classifier *(currently blocked: split script not optimized yet)*.

## 2. Prerequisites

### Hardware

- **GPU strongly recommended.** Configs default to `device: "cuda"` and were tuned on an RTX 4080 (batch size 8192). The training scripts will silently fall back to CPU if CUDA is unavailable, but a full RAT-medium run on CPU is impractical.
- **RAM:** at least 16 GB for HI-Small, 32 GB+ recommended for HI-Medium graph builders (RAT injection holds the full DataFrame in memory).
- **Disk:** ~10 GB free for the IBM CSVs, pre-built graphs, splits, results, and logs combined.

### Software

- **OS:** Linux, macOS, or Windows. All Python scripts resolve paths from the script's own location (`Path(__file__).resolve().parents[...]`), so no editing is required after `git clone`. The bash drivers under `scripts/bash/` auto-detect a conda install in the standard Linux / macOS / Windows-GitBash locations; override with `CONDA_EXE=...` or `CONDA_ENV=...` if needed.
- **Python:** 3.10 (the conda env pins `python=3.10.19`).
- **CUDA:** 12.1 to match the pinned `torch==2.5.1+cu121`. The conda env file pulls a full `cuda-toolkit=13.0.2`, but PyTorch wheels themselves use the cu121 runtime. Either works; the cu121 PyTorch wheel ships its own runtime libs.
- **Git LFS:** required to clone the dataset CSVs from this repo (`*.csv` is LFS-tracked per `.gitattributes`).

## 6. Running the Models

All training scripts share the same CLI (`--config`, `--dataset`, `--base_config`, optional `--intensity`). Always run from the project root so the relative paths inside the configs resolve correctly.

### 6.1 GraphSAGE (static)

```bash
python scripts/training/train_graphsage.py \
    --config configs/models/graphsage.yaml \
    --dataset configs/datasets/rat.yaml \
    --base_config configs/base.yaml \
    --intensity low
```

For the non-injected baseline dataset, drop `--intensity` and point at the baseline dataset config:

```bash
python scripts/training/train_graphsage.py \
    --config configs/models/graphsage.yaml \
    --dataset configs/datasets/baseline.yaml \
    --base_config configs/base.yaml
```

### 6.2 GraphSAGE-T (temporal)

```bash
python scripts/training/train_graphsage_t.py \
    --config configs/models/graphsage_t.yaml \
    --dataset configs/datasets/rat.yaml \
    --base_config configs/base.yaml \
    --intensity low
```

### 6.3 Running on SLT-injected data

The pipeline is identical for **SLT (Social Learning Theory)** features — just swap the dataset config. Anywhere the RAT examples above use `configs/datasets/rat.yaml`, use `configs/datasets/slt.yaml` instead. `--intensity` still takes `low`, `medium`, or `high`, and the same three model scripts (`train_graphsage.py`, `train_graphsage_t.py`, `train_dyrep.py`) work without modification because the motif graph builders auto-detect `SLT_*` columns the same way they auto-detect `RAT_*` columns.

```bash
# GraphSAGE on SLT-medium
python scripts/training/train_graphsage.py \
    --config configs/models/graphsage.yaml \
    --dataset configs/datasets/slt.yaml \
    --base_config configs/base.yaml \
    --intensity medium

# GraphSAGE-T on SLT-low
python scripts/training/train_graphsage_t.py \
    --config configs/models/graphsage_t.yaml \
    --dataset configs/datasets/slt.yaml \
    --base_config configs/base.yaml \
    --intensity low
```

Outputs land under the corresponding `HI-{Small,Medium}_Trans_SLT_{intensity}` dataset folders in `graphs/`, `splits/`, `results/`, and `logs/`.

## 7. Configuration System

`scripts/utils/config_utils.py::setup_experiment` does all the wiring:

1. Loads `base`, `model`, and `dataset` YAML files and merges them.
2. Validates that the dataset+intensity combination is allowed.
3. Sets all PyTorch / NumPy / Python random seeds from `base.experiment.seed`.
4. Builds paths:
   - `dataset_name = "{prefix}_{intensity}"` (or just `prefix` for baseline).
   - `graph_folder = paths.graphs_dir / dataset_name` (or `dyrep_graphs_dir` for DyRep).
   - `split_folder = paths.splits_dir / dataset_name` (or `dyrep_splits_dir`).
   - `results_dir = paths.results_dir / dataset_name / "seed{seed}_{name}" / model_name`.
   - `logs_dir   = paths.logs_dir   / dataset_name / "seed{seed}_{name}" / model_name`.
5. Initialises a `Logger` that mirrors `stdout` and `stderr` to a timestamped file under `logs_dir`.
6. Picks the device (`cuda` if available, otherwise `cpu`).

### Editing common knobs

- **Seed / experiment name:** `configs/base.yaml → experiment.{seed,name}`.
- **Evaluation threshold + top-k:** `configs/base.yaml → evaluation`.
- **Hidden dim, layers, dropout, time encoding:** `configs/models/<model>.yaml → model`.
- **Batch size, LR, epochs, early-stopping patience, optimizer, gradient clip:** `configs/models/<model>.yaml → training`.
- **Loss / pos_weight:** `configs/models/<model>.yaml → loss`. Leave `pos_weight: null` to auto-compute from the train split (capped at 100 for stability).
- **Default dataset prefix:** `configs/datasets/rat.yaml → dataset.prefix`. The shipped default is `HI-Medium_Trans_RAT`; change to `HI-Small_Trans_RAT` to use the small graphs.

## 8. Outputs

Each training run produces, under `results/<dataset>/<experiment>/<model>/`:

| File                       | Contents                                                                       |
|----------------------------|--------------------------------------------------------------------------------|
| `best_model.pt`            | Model state-dict at the best validation AUPR epoch                             |
| `metrics.json`             | Train / val / test metrics, best epoch, total training time, batch sizes       |
| `train_pred_probs.pt`      | Per-edge predicted probabilities on the train split                            |
| `val_pred_probs.pt`        | Per-edge predicted probabilities on the val split                              |
| `test_pred_probs.pt`       | Per-edge predicted probabilities on the test split                             |
| `experiment_config.json`   | Snapshot of base+model+dataset configs, intensity, and additional metadata     |

Logs land under `logs/<dataset>/<experiment>/<model>/`:

- `<experiment>_<timestamp>.txt` — full stdout
- `<experiment>_<timestamp>_errors.txt` — stderr
- `tb/` — TensorBoard event files (`Loss/train`, `Val/F1`, `Val/AUPR`, `Time/epoch_seconds`)

View training curves with:

```bash
tensorboard --logdir logs
```

The metrics computed by `scripts/utils/evaluation_utils.py::evaluate_binary_classifier` are imbalance-aware: precision, recall, F1, AUPR (average precision), ROC-AUC, balanced accuracy, MCC, Cohen's kappa, confusion-matrix counts, plus optional precision@k / recall@k for `k ∈ {100, 500, 1000}` and an auto-tuned operating threshold.

## 9. Building Graphs from Scratch (Optional)

You only need this if you don't want to use the pre-built `.pt` graphs from Drive.

All injector and graph-builder scripts resolve their input/output paths from the script's own location, so they work on any OS without editing as long as the repo layout is intact (i.e. `scripts/...` and `ibm_transcations_datasets/` sit at the repo root).

### Step 1 — Theory feature injection

#### Step 1a — RAT injector

```bash
python scripts/rat/rat_injector.py
```

Reads `HI-Medium_Trans.csv` + `HI-Medium_accounts.csv` (+ optional `HI-Medium_patterns.txt`), computes RAT sub-scores and motif features, and writes:

```
ibm_transcations_datasets/RAT/
├── HI-Medium_Trans_RAT_low.csv
├── HI-Medium_Trans_RAT_medium.csv
└── HI-Medium_Trans_RAT_high.csv
```

The intensity threshold is the `1 - frac` quantile of the RAT score over the laundering-positive rows (`low=0.15`, `medium=0.30`, `high=0.60`).

#### Step 1b — SLT injector (alternative theory)

The SLT pipeline is structurally identical to RAT — a separate injector script under `scripts/SLT/` produces the same `{low, medium, high}` intensity files, just with `SLT_*` prefixed feature columns instead of `RAT_*`:

```bash
python scripts/SLT/slt_injector.py
```

Outputs:

```
ibm_transcations_datasets/SLT/
├── HI-Small_Trans_SLT_low.csv
├── HI-Small_Trans_SLT_medium.csv
└── HI-Small_Trans_SLT_high.csv
```

Steps 2 and 3 below (graph building and split creation) are **unchanged** for SLT — the motif graph builders auto-detect the `SLT_` prefix the same way they detect `RAT_`, so the same `motif_graph_builder_static.py` / `motif_dyrep_graph_builder.py` scripts work without modification. Just edit the `DATASET = ...` line at the top of the builder to point at the SLT CSV (e.g. `HI-Small_Trans_SLT_medium`).

### Step 2 — Build the graph tensors

For static GraphSAGE / GraphSAGE-T:

```bash
# baseline (no theory)
python scripts/graph/baseline_graph_builder.py

# RAT/motif features (edit DATASET = ... at the top of the file
# to choose low / medium / high and Small / Medium)
python scripts/graph/motif_graph_builder_static.py
```

For DyRep event graphs:

```bash
python scripts/graph/baseline_dyrep_graph_builder.py
python scripts/graph/motif_dyrep_graph_builder.py     # edit DATASET as above
```

### Step 3 — Create train/val/test splits

`create_splits.py` auto-detects the graph type:

- Static (`edge_index.pt` present) → stratified random 60/20/20 (by `y_edge`).
- DyRep (`src.pt + dst.pt + ts.pt`) → chronological 60/20/20.

```bash
python scripts/create_splits.py \
    --graph_folder graphs/HI-Medium_Trans_RAT_low \
    --out_dir splits/HI-Medium_Trans_RAT_low \
    --train_ratio 0.60 --val_ratio 0.20 --test_ratio 0.20 \
    --seed 42
```

If `--out_dir` is omitted it defaults to `<graph_folder_parent>/../splits/<dataset_name>`.

## 10. Ablation Studies

Ablations strip groups of features out of an existing graph's `edge_attr.pt` and write a new graph folder you can train on without re-injecting or re-building.

### Defined feature groups

`scripts/ablations/rat_ablation_groups.py` defines: `no_struct`, `no_temp`, `no_amount`, `no_burst_pattern`, `no_entity`, `no_rat_scores`, `no_motif`, `no_crossbank`, and `top20_features` (a *positive* selection of the top-20 RF-important features rather than a removal).

### Build all ablation graphs

```bash
cd scripts/ablations
python run_all_ablation_graphs.py
```

By default this reads from `graphs_dyrep/HI-Small_Trans_RAT_medium`. To run ablations against a different source graph, edit the `FULL = ...` line at the top of the script.

This produces sibling folders next to the source graph (e.g. `graphs_dyrep/HI-Small_Trans_RAT_medium__no_struct`).

### Build a single ablation

```python
from scripts.ablations.run_ablation import run_ablation
from scripts.ablations.rat_ablation_groups import FULL_FEATURES, NO_MOTIF

keep = [f for f in FULL_FEATURES if f not in NO_MOTIF]
run_ablation(
    full_graph_dir="graphs_dyrep/HI-Small_Trans_RAT_medium",
    output_dir="graphs_dyrep/HI-Small_Trans_RAT_medium__no_motif",
    keep_features=keep,
)
```

### Train on an ablation graph

Train as normal, but point the dataset config (`prefix`) — or pass a `--graph_suffix` if you've added that flag to your training script — at the ablation folder name. `scripts/bash/run_ablations.sh` shows the intended pattern.

## 12. Bash Driver Scripts

The scripts under `scripts/bash/` chain multiple training runs with timestamped logs in `logs/`. They auto-detect a conda install in the usual Linux (`~/anaconda3`, `~/miniconda3`, `/opt/conda`, ...), macOS, and Windows-GitBash (`/c/ProgramData/Anaconda3`) locations. To force a specific install or env name:

```bash
# pick a non-default conda
CONDA_EXE=/path/to/your/conda bash scripts/bash/run_rat_all.sh

# pick a non-default env name
CONDA_ENV=my_env bash scripts/bash/run_rat_all.sh
```

| Script              | Runs                                                                          |
|---------------------|-------------------------------------------------------------------------------|
| `run_baseline.sh`   | Selected baseline models on the non-injected dataset                          |
| `run_rat_all.sh`    | GraphSAGE + GraphSAGE-T (and optionally DyRep) on RAT low / medium / high     |
| `run_dyrep.sh`      | DyRep on baseline + RAT low / medium / high                                   |
| `run_ablations.sh`  | DyRep on the 9 ablation graphs (RAT-medium)                                   |
| `run_all.sh`        | All models × all datasets in a single sweep                                   |

Run from the repo root:

```bash
bash scripts/bash/run_rat_all.sh
```

Logs are written to `logs/rat_all_<timestamp>.log` and a `logs/RAT_ALL_FINISHED_<timestamp>.done` marker file is touched on success.

## 13. Troubleshooting

**`torch.cuda.is_available()` returns `False`.**
Verify the installed wheel is a `+cuXXX` build (`pip show torch`) and that your driver supports CUDA 12.1+ (`nvidia-smi`). Re-install via the PyTorch index URL shown in [§3](#3-installation).

**`FileNotFoundError: graphs/HI-Medium_Trans_RAT_low/edge_index.pt`.**
The pre-built graphs from Drive haven't been extracted in the right place, or you didn't pass `--intensity`. Check `configs/datasets/rat.yaml` (`prefix: HI-Medium_Trans_RAT`) — the resolved folder is `graphs/{prefix}_{intensity}`.

**`FileNotFoundError: splits/...`.**
Pre-built splits cover only `splits/HI-Medium_Trans_RAT_low`. For other intensities or sizes, run `scripts/create_splits.py` against the matching graph folder.

**Out-of-memory on GPU.**
Lower `training.batch_size` / `training.eval_batch_size` in the model YAML. The defaults assume ~16 GB VRAM (RTX 4080).

**Out-of-memory on CPU during graph build.**
The `motif_graph_builder_static.py` and `rat_injector.py` scripts hold the full HI-Medium DataFrame (~30 M rows) in memory. Use the HI-Small variants on a low-RAM machine.

**`run_*.sh` errors with "could not locate a conda install".**
The bash drivers probe for conda in `$CONDA_EXE`, then on `$PATH`, then in the standard install locations. If none of those match your setup, set `CONDA_EXE` to your `conda` binary before running:

```bash
CONDA_EXE=/path/to/conda bash scripts/bash/run_rat_all.sh
```

If your env is not named `aml_project`, set `CONDA_ENV` similarly.

**DyRep training errors.**
Per the project status, DyRep splits are not yet optimised — the script is functional but the surrounding split pipeline needs work. Stick to GraphSAGE / GraphSAGE-T for reproducible results.

**`FileNotFoundError` from a graph builder or injector.**
The graph builders and theory injectors resolve paths from their own location (`Path(__file__).resolve().parents[2]` → repo root). If you've moved a script outside the `scripts/<subdir>/` layout, update the `parents[N]` index, or move the script back into the standard layout.
